## P3==0 停机判断偶发失效的诊断（仅分析，未改代码）
用户明确：循迹传感器一定能全黑，排除硬件 / 8 位不能同时为 0 的方向。结论落在纯代码时序：
- 主循环是轮询采样；Delay(300)/Delay(200)/声光提示约 3s/报警循环/chaoshengbo() 等回波空转期间完全不读 P3。A 点线是"经过"不是"停留"，窗口几十 ms，落进盲区就漏判，表现为"有时"。
- renwu4 把 if(P3==0) 放在 chaoshengbo() 与避障处理之后（renwu.c:235），判的是过线之后的状态；renwu1 放在循环首句（:13）可靠得多。
- renwu3 的 while(P3==0);（:146）在车已停住（CompareR/L=0，:141 的 Speed=100 未写回比较值）时永远等不到 P3 变 1，tingguo 卡在 1，:149 停机分支不可达。renwu2 的同类 while（:63）内部给了前进 PWM 所以能退出。
- renwu4 的 else { likai=1; }（:248）隐含"起点必须压在线上"的前提。
- 最彻底方案：在 Timer0_Routine() 的 100us 中断里读 P3 并置 bit 标志，主循环只清标志处理，中断不受 Delay 阻挡。
